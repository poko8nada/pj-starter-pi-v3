# thinking-scrub

English: [README.md](README.md)

ループした thinking は、生成中に 20,000 文字で文の周期があれば止め、`message_end` で畳むため、壊れた推論は次のリクエストに持ち越さない。文の周期は 3 回以上・400 文字以上・周期 1〜64 単位、文字の周期は周期 4〜120 文字・3 回以上・20 文字以上が条件になる。それ以外の本文には触らない。

## コマンド

`/thinking-scrub` は scrub の有効・無効、実行終わりの報告の表示・非表示を切り替え、セッションの状態を見せる。`settings.json` を書き換えるのは `on` / `off` / `show` / `hide` だけになる。

```
/thinking-scrub        有効・消した回数・最後の scrub 時刻を見る
/thinking-scrub on     ループした thinking を畳む
/thinking-scrub off    thinking に触らない
/thinking-scrub show   実行の終わりに畳んだ集計を出す（既定）
/thinking-scrub hide   実行の終わりの報告を出さない
```

それ以外の引数は投げずに使い方を出す。

## 設定

`settings.json` はこのファイルの隣にあり、`enabled` と `show`、調整の `live`、`sentence`、`char` の 3 グループを持つ。手編集は次のスキャンから効き、`message_end` とコマンドはすぐに読み直す。ファイルが無いときは有効で報告ありとして動き、壊れているときは既定で動く。

```json
{
  "enabled": true,
  "show": true,
  "live": {
    "minThinking": 20000,
    "scanEvery": 2000,
    "tail": 20000,
    "maxAborts": 2,
    "sampleChars": 200
  },
  "sentence": { "minCycles": 3, "minRunChars": 400, "maxPeriodUnits": 64 },
  "char": { "minPeriod": 4, "maxPeriod": 120, "minRepeats": 3, "minLength": 20 }
}
```

無いキーは上の既定になる。型違い、範囲外、`scanEvery` が `tail` を超える、`minPeriod` が `maxPeriod` を超える、`minRepeats` が 2 未満は broken になる。

### `live`：生成中の停止

| キー          | 説明                               | 既定    | 上げたとき                               | 下げたとき                                 | 注意                                  |
| ------------- | ---------------------------------- | ------- | ---------------------------------------- | ------------------------------------------ | ------------------------------------- |
| `minThinking` | スキャンを始める thinking の長さ。 | `20000` | 反応が遅くなり、読みが減る。             | 反応が早くなり、読みが増える。             | 手編集は次のスキャンから効く。        |
| `scanEvery`   | スキャンの間隔（新しい文字数）。   | `2000`  | 読みが減り、反応はこの文字数だけ遅れる。 | 反応が早くなり、読みが増える。             | `tail` 以下にする。                   |
| `tail`        | 1 回のスキャンが読む末尾の窓。     | `20000` | 離れた周期も拾い、1 回の重さが増す。     | 軽くなるが、窓の外の周期は逃す。           | 窓の外の周期は `idle` になる。        |
| `maxAborts`   | user 1 回あたりの停止回数。        | `2`     | 諦めるまでの割り込みが増える。           | 割り込みが減り、`0` で生成中の停止を切る。 | 上限後も `scanned` は進み、読まない。 |
| `sampleChars` | フォローアップの見本の長さ。       | `200`   | 見本が長くなる。                         | 見本が短くなる。                           | 残る見本の上限にもなる。              |

### `sentence`：文の周期（停止と畳み込み）

| キー             | 説明                           | 既定  | 上げたとき                       | 下げたとき                             | 注意                            |
| ---------------- | ------------------------------ | ----- | -------------------------------- | -------------------------------------- | ------------------------------- |
| `minCycles`      | 周期と数える文の繰り返し回数。 | `3`   | 拾う数が減る。                   | 拾う数が増える。                       | 下限は `2`。                    |
| `minRunChars`    | 文の周期の最短の長さ。         | `400` | 拾う数が減る。                   | 拾う数が増え、短い繰り返しが誤爆する。 | 畳むときは最初の 1 周期を残す。 |
| `maxPeriodUnits` | 読む文の周期の上限（単位）。   | `64`  | 範囲が広がり、1 回の重さが増す。 | 軽くなるが、長い周期は逃す。           | 重なる周期は小さい方を残す。    |

### `char`：文字の周期（畳み込みだけ）

| キー         | 説明                             | 既定  | 上げたとき                           | 下げたとき                             | 注意                                                 |
| ------------ | -------------------------------- | ----- | ------------------------------------ | -------------------------------------- | ---------------------------------------------------- |
| `minPeriod`  | 数える文字の周期の下限（文字）。 | `4`   | 短い周期は無視する。                 | 拾う数が増え、短い繰り返しが誤爆する。 | 短い周期を除く境目にもなる。`maxPeriod` 以下にする。 |
| `maxPeriod`  | 読む文字の周期の上限（文字）。   | `120` | 範囲が広がり、畳み込みの重さが増す。 | 軽くなるが、長い周期は逃す。           | 文字の周期の走査の上限になる。                       |
| `minRepeats` | 周期と数える文字の繰り返し回数。 | `3`   | 厳しくなり、拾う数が減る。           | 拾う数が増える。                       | 下限は `2`。                                         |
| `minLength`  | 文字の周期の最短の長さ。         | `20`  | 厳しくなり、拾う数が減る。           | 拾う数が増え、短い繰り返しが誤爆する。 | この長さ未満の区間は残す。                           |

### 組み合わせ

- 周期の決め方を変えずに早く反応する：`live.minThinking` と `live.scanEvery` を一緒に下げる（例は `8000` / `1000`）。`sentence` と `char` はそのままにする。
- 長い周期だけ静かに畳む：`sentence.minRunChars`（例は `350` から上へ）と `char.minLength` を一緒に上げる。
- スキャンを軽くする：`live.tail`、`sentence.maxPeriodUnits`、`char.maxPeriod` を一緒に下げる。1 回の読みが狭くなる。
- `live.scanEvery` を `live.tail` より上げない。`char.minPeriod` を `char.maxPeriod` より上げない。どちらも broken になる。

### 調整例：`8000` / `1000` / `350`

定数を外に出した後の最初の調整は、周期の決め方を残して早く反応する：

```json
{
  "live": { "minThinking": 8000, "scanEvery": 1000 },
  "sentence": { "minRunChars": 350 }
}
```

- `live.minThinking: 8000` — 20,000 文字ではなく 8,000 文字からスキャンを始める。
- `live.scanEvery: 1000` — 始めた後は 1,000 文字ごとに読む。手編集は次のスキャンから効く。
- `sentence.minRunChars: 350` — 文の周期は 350 文字から数え、`minCycles` の 3 回は残すため少し短い周期も畳む。

## 対象のブロック

生成中の検出は署名を求めずに流れる thinking を読む。`message_end` の畳み込みは今の署名の決まりを保つ：`thinkingSignature` が `reasoning_content`、`reasoning`、`reasoning_text` の thinking だけを書き換える。署名無し・JSON 署名・`redacted` には触らない。区間を消した繋ぎ目は、消した区間に改行があれば改行を戻し（`\n\n` が `\n` に勝つ）、無ければ前後がどちらも非空白のときだけ空白 1 個を足す。

## フォローアップ

`agent_settled` では回数の多い 3 文の見本を持つ custom メッセージを送り、次の実行を始める。

## 実行終わりの報告

実行の終わり（`agent_end`）に、`show` が有効で何か畳んでいれば 1 行出す：`thinking-scrub: removed <runs> (<chars> chars)`。集計は報告のたびに戻るため、次の実行は自分の分だけ出す。
