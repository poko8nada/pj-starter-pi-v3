# thinking-scrub

English: [README.md](README.md)

ループした thinking は、生成中に 20,000 文字以上になった後は文の周期があれば停止し、`message_end` で畳み込むため、壊れた推論は次のリクエストに持ち越されない。文の周期の条件は 3 回以上の繰り返し・400 文字以上の長さ・1〜64 単位の周期であり、文字の周期の条件は 4〜120 文字の周期・3 回以上の繰り返し・20 文字以上の長さである。それ以外のテキストには触れない。

## コマンド

`/thinking-scrub` は scrub の有効化・無効化と、実行終わりの報告の表示・非表示を切り替え、セッションの状態を表示する。`settings.json` を書き換えるのは `on` / `off` / `show` / `hide` の場合に限られる。

```
/thinking-scrub        有効状態・削除回数・最後の scrub 時刻を見る
/thinking-scrub on     ループした thinking を畳む
/thinking-scrub off    thinking に触らない
/thinking-scrub show   実行終わりの報告を表示する（既定）
/thinking-scrub hide   実行終わりの報告を表示しない
```

それ以外の引数が渡された場合は、エラーを投げずに使い方を表示する。

## 設定

`settings.json` はこのファイルの隣にあり、`enabled` と `show`、`live`・`sentence`・`char` の 3 グループを持つ。手編集した内容は次のスキャンから反映され、`message_end` とコマンドではすぐに読み直される。ファイルが無い場合は有効かつ報告ありとして動作し、ファイルが壊れている場合は既定値で動作する。

```json
{
  "enabled": true,
  "show": true,
  "live": {
    "minThinking": 20000,
    "scanEvery": 2000,
    "tail": 20000,
    "maxAborts": 2,
    "sampleChars": 200
  },
  "sentence": { "minCycles": 3, "minRunChars": 400, "maxPeriodUnits": 64 },
  "char": { "minPeriod": 4, "maxPeriod": 120, "minRepeats": 3, "minLength": 20 }
}
```

存在しないキーは上記の既定値になる。型の不一致、範囲外、`scanEvery` が `tail` を超える場合、`minPeriod` が `maxPeriod` を超える場合、`minRepeats` が 2 未満の場合は不正とみなされる。

### `live`：生成中の停止

| キー          | 説明                                   | 既定    | 上げたとき                                             | 下げたとき                                             | 注意                                                |
| ------------- | -------------------------------------- | ------- | ------------------------------------------------------ | ------------------------------------------------------ | --------------------------------------------------- |
| `minThinking` | スキャンを開始する thinking の長さ。   | `20000` | 検出が遅くなり、読み取り量が減る。                     | 検出が早くなり、読み取り量が増える。                   | 手編集した内容は次のスキャンから反映される。        |
| `scanEvery`   | スキャンの間隔（新たに増えた文字数）。 | `2000`  | 読み取り量が減り、検出はその文字数分だけ遅れる。       | 検出が早くなり、読み取り量が増える。                   | `scanEvery` を `tail` 以下にすること。              |
| `tail`        | 1 回のスキャンで読む末尾のウィンドウ。 | `20000` | 離れた位置の周期も検出できるが、1 回の処理が重くなる。 | 処理は軽くなるが、ウィンドウの外の周期は検出できない。 | ウィンドウの外の周期は検出対象外（`idle`）になる。  |
| `maxAborts`   | ユーザー要求 1 回あたりの停止回数。    | `2`     | 停止を打ち切るまでの割り込み回数が増える。             | 割り込み回数が減り、`0` では生成中の停止が無効になる。 | 上限後も `scanned` は進むが、読み取りは行われない。 |
| `sampleChars` | フォローアップに付ける見本の長さ。     | `200`   | 見本が長くなる。                                       | 見本が短くなる。                                       | 残す見本の長さの上限にもなる。                      |

### `sentence`：文の周期（停止と畳み込み）

| キー             | 説明                                     | 既定  | 上げたとき                               | 下げたとき                                 | 注意                                       |
| ---------------- | ---------------------------------------- | ----- | ---------------------------------------- | ------------------------------------------ | ------------------------------------------ |
| `minCycles`      | 周期とみなすための文の繰り返し回数。     | `3`   | 検出数が減る。                           | 検出数が増える。                           | 値の下限は `2` である。                    |
| `minRunChars`    | 文のランとして認める最短の長さ。         | `400` | 検出数が減る。                           | 検出数が増え、短い繰り返しが誤検出される。 | 畳み込む際は最初の 1 周期を残す。          |
| `maxPeriodUnits` | 走査対象とする文の周期の上限（文単位）。 | `64`  | 走査範囲が広がり、1 回の処理が重くなる。 | 処理は軽くなるが、長い周期は検出できない。 | 重なる周期がある場合は小さい方が残される。 |

### `char`：文字の周期（畳み込みだけ）

| キー         | 説明                                     | 既定  | 上げたとき                                   | 下げたとき                                 | 注意                                                                        |
| ------------ | ---------------------------------------- | ----- | -------------------------------------------- | ------------------------------------------ | --------------------------------------------------------------------------- |
| `minPeriod`  | 周期として数える文字数の下限（文字数）。 | `4`   | 短い周期は無視される。                       | 検出数が増え、短い繰り返しが誤検出される。 | 短い周期を除外する境目にもなる。`minPeriod` を `maxPeriod` 以下にすること。 |
| `maxPeriod`  | 走査する文字の周期の上限（文字数）。     | `120` | 走査範囲が広がり、畳み込み処理の負荷が増す。 | 処理は軽くなるが、長い周期は検出できない。 | 文字周期の走査範囲の上限になる。                                            |
| `minRepeats` | 周期とみなすための文字の繰り返し回数。   | `3`   | 条件が厳しくなり、検出数が減る。             | 検出数が増える。                           | 値の下限は `2` である。                                                     |
| `minLength`  | 文字のランとして認める最短の長さ。       | `20`  | 条件が厳しくなり、検出数が減る。             | 検出数が増え、短い繰り返しが誤検出される。 | この長さ未満の区間は残される。                                              |

### 組み合わせ

- 検出条件を変えずに早く反応させるには、`live.minThinking` と `live.scanEvery` を一緒に下げる（例：`8000` / `1000`）。`sentence` と `char` の設定は変えない。
- 長いランだけ静かに畳むには、`sentence.minRunChars`（例：`350` からさらに上げる）と `char.minLength` を一緒に上げる。
- スキャンを軽くするには、`live.tail`、`sentence.maxPeriodUnits`、`char.maxPeriod` を一緒に下げる。1 回に読む範囲が狭くなる。
- `live.scanEvery` を `live.tail` より大きくしないこと。`char.minPeriod` を `char.maxPeriod` より大きくしないこと。いずれに該当する場合も不正とみなされる。

### 調整例：`8000` / `1000` / `350`

定数を外出しした後の最初の調整では、検出条件を保ったまま早く反応させる：

```json
{
  "live": { "minThinking": 8000, "scanEvery": 1000 },
  "sentence": { "minRunChars": 350 }
}
```

- `live.minThinking: 8000` — 20,000 文字からではなく 8,000 文字からスキャンを開始する。
- `live.scanEvery: 1000` — 開始後は 1,000 文字ごとに読み取る。手編集した内容は次のスキャンから反映される。
- `sentence.minRunChars: 350` — 文のランは 350 文字以上を対象とし、`minCycles` の 3 回という条件は保つため、1 周期が短い繰り返しも畳み込む。

## 対象のブロック

生成中の検出では、署名を求めずに流れてくる thinking を読む。`message_end` での畳み込みは現在の署名の規則に従う：`thinkingSignature` が `reasoning_content`、`reasoning`、`reasoning_text` である thinking だけを書き換える。署名なしのブロック・JSON 署名のブロック・`redacted` のブロックには触れない。区間を削除した後のつなぎ目では、削除した区間に改行が含まれていれば改行を補い（`\n\n` を `\n` より優先する）、含まれていなければ前後の文字がどちらも非空白の場合に限り空白 1 個を補う。

## フォローアップ

`agent_settled` では、出現回数の多い 3 文の見本を含むカスタムメッセージが送られ、次の実行が開始される。

## 実行終わりの報告

実行終わり（`agent_end`）に、`show` が有効であり何らかを畳んでいれば 1 行表示する：`thinking-scrub: removed <runs> (<chars> chars)`。集計は報告のたびにリセットされるため、次の実行では自分の分だけが報告される。
