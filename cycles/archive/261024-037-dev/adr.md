# ADR 037

## 01: 生成中のループを止めるか

### Context

- 直前のセッションで、thinking が約 950 文字の周期を約 260 回繰り返し、1 メッセージで 517,818 文字になった。
- そのメッセージは 8 分 4 秒生成を続け、owner の abort で止まった。
- 既存の scrub は `message_end` で畳むだけで、生成中は止めない。ADR 028 は `ctx.abort()` を持たないと決めた。
- owner は、ループを生成中に捕まえて止め、フォローアップで注意してそのまま続行することを求めた。
- 20,000 文字未満の小さなループは、自然に終わらせて `message_end` で畳む。
- 分かっていないこと: フォローアップを送った後に、ループが実際に止まるか。既存のツールにも報告が無い。

### Scope

- 変更:
  - behaviour: in — thinking が 20,000 文字以上で周期を検出したら `ctx.abort()` し、`agent_settled` で custom message を送る。abort は 1 run 2 回まで。
  - refactor: in — 検出の芯を単位で切り替えられる形にする。entry 02 と共有する。
  - dependency: out — 新しい依存は無い。純粋なロジックと Node の標準機能だけで書ける。
  - naming: out — 既存の名前は変えない。新しい名前は新しいロジックと一緒に付く。
  - format: out — 形だけを変える箇所は無い。
  - prose: in — `thinking-scrub/README.md` とコメント。
- 品質:
  - speed: in — live の走査は末尾の窓に限り、全文を毎デルタで回さない。
  - security: out — 新しい入力面が無い。モデル自身の thinking を読み、設定を書くだけ。
  - compatibility: in — `settings.json`、`/thinking-scrub`、既存テストを壊さない。
  - errors: in — live の経路は投げない。二重の abort を防ぐ。abort の回数に上限を置く。
- 運用:
  - deploy: out — このスターターに deploy は無い。
  - migration: out — 既存のセッションは書き換えない。
  - logs and monitoring: out for now — フォローアップと abort はトランスクリプトに出る。既存の集計は残す。止めた理由が見えなくなったら再訪する。

### Research & Trial

- 649 の thinking は、約 950 文字の周期が約 260 回連続した区間を含む。`stopReason` は `aborted`、`durationMs` は 484,130。
- センテンス検出は、1,010 ブロック・4,619,187 文字で 14 クラスタを検出し、すべて本物のループだった。正常な 5 セッション・779 ブロックは 0 件。
- 最初に鳴る位置は、633 が 4,400 文字、649 が 11,900 文字（100 文字刻み）。
- B の 20,000 文字では、633・640・644 は畳むだけ、642 は 25,100、509 は 22,700、649 は 20,000 で止まる。
- 末尾 20,000 文字の検出は 0.2 ms、最大ブロック全文 517,818 文字は 6.5 ms、2,000 文字ごとの全文再走査は合計 1,228.7 ms だった。
- `agent-loop.js` は `stopReason: "aborted"` で即 return し、follow-up も steer も drain しない。`agent_settled` 中の `sendUserMessage` と `sendMessage(triggerTurn)` は settle 後に遅延実行される（`agent-session.js` 1603-1606、1837-1841）。
- loop-police は stream を abort して回復メッセージを送る。pi-repetition-guard は `ctx.abort()` の後に steer を送り、1 論理ターン 2 回までにする。antiloop は警告のみ、または次の LLM 呼び出し前に user message を送る。
- どのツールも、止めた後にループが実際に止まったという報告を持っていない。trial はしていない。ループは狙って起こせない。

### Decision

- Status: **accepted**
- Adopted:
  - **B**: 現在の assistant メッセージの thinking が 20,000 文字以上で、センテンス検出が run を見つけたら `ctx.abort()` する。`agent_settled` で custom message（`triggerTurn: true`）を送り、次の run を始める。abort は 1 run 2 回まで。上限の後は abort せず、`message_end` の畳み込みだけを行う。
- Options:
  - **A**: 最初の検出（3 周期、400 文字以上）で abort する。買うもの: 633 の 4,400 文字で止まり、最も早い。コスト: 小さなループや正当な 3 回の繰り返しでも abort する。abort の回数が増える。成り立たない所: 自然に終わる小さなループ。（採らなかった理由: B で 517k は避けられ、小さなループは畳めば足りる）
  - **C**: 止めない。買うもの: 生成を捨てない。フォローアップの未証明リスクが無い。コスト: 517,818 文字 / 8 分の生成が起きる。owner が手で abort する。成り立たない所: 意図の「生成中に止める」。（採らなかった理由: 意図を満たさない）
  - **D**: steer で警告する。買うもの: 既存の antiloop に近い。コスト: abort した run では steer も follow-up も drain されない。abort しない steer は現在のターンが終わるまで届かない。成り立たない所: 止まらない、または届かない。（採らなかった理由: 止まらない、または届かない）

### Definition

- `Unit.thinking-scrub`(kept): ループを次のターンに持ち越さない main function は同じ。生成中に止めるのは新しい route。

## 02: 検出の単位をセンテンスにするか

### Context

- 既存の検出は文字単位で、周期 4〜120 文字、3 回以上、20 文字以上を見る。649 の 947 文字周期は上限を超え、1 文字も捕まえなかった。
- owner は、文や段落の単位で繰り返しを見る検出を求めた。パラグラフは 1 段落内の文の繰り返しを見落とすので、センテンスにする。
- 文字単位は、文中の `the the the` のようなゴミのために残す。
- ガードとして、コードフェンス、表の行、diff の行を不透明な単位にする。
- 分かっていないこと: 他のモデルでも同じ誤検出率になるか。

### Scope

- 変更:
  - behaviour: in — センテンス単位の検出とガードを足す。最初の 1 周期を残す。
  - refactor: in — `detect.ts` の周期走査を単位で使える形にする。
  - dependency: out — 新しい依存は無い。
  - naming: out — 既存の名前は変えない。
  - format: out — 形だけを変える箇所は無い。
  - prose: in — README とコメント。
- 品質:
  - speed: in — 末尾の窓に限り、全文を毎デルタで回さない。
  - security: out — 新しい入力面が無い。
  - compatibility: in — 既存の文字単位の検出を残す。`isReplayable` の規則を変えない。
  - errors: in — 検出の例外は投げない。
- 運用:
  - deploy: out — このスターターに deploy は無い。
  - migration: out — 既存のセッションは書き換えない。
  - logs and monitoring: out — 既存の集計を残す。

### Research & Trial

- 1,010 ブロック・4,619,187 文字で、14 クラスタを検出した。すべて本物のループで、正当な繰り返しは 0 件だった。
- 正常な 5 セッション・779 ブロックは 0 件だった。モデルはすべて `opencode-go/deepseek-v4.1-flash`。
- 検出条件は、行 → 文に分割、周期 1〜64 単位、3 周期以上、区間 400 文字以上、コードフェンス・表・diff を不透明単位にし、その単位を含む区間は捨てる。
- 取り逃がす形は、400 文字未満の短い周期（`Hmm.` 129 回、`fine.` 132 回）、周期 64 単位超、3 周期未満、不透明単位を含む区間、分散反復、言い換え。
- 文分割の異常は、番号付きリスト（`1.` `2.`）、`No.`、`E.g.`、小文字始まり。14 クラスタには含まれず、誤検出の原因にはなっていない。番号は単位を砕き、周期を膨らませる。
- 所要時間は、最大ブロック全文 6.5 ms、末尾 20,000 文字 0.2 ms、2,000 文字ごとの全文再走査 1,228.7 ms。
- trial はしていない。

### Decision

- Status: **accepted**
- Adopted:
  - **センテンス単位 + 文字単位**: センテンスは行 → 文、周期 1〜64 単位、3 周期以上、400 文字以上、フェンス・表・diff は不透明単位、最初の 1 周期を残す。文字は既存のまま全部消す。順序はセンテンス、その残りに文字。
- Options:
  - **センテンスだけ**: 買うもの: 検出が 1 種類になる。コスト: 文中の `the the` を落とす。成り立たない所: 文の中のゴミ。（採らなかった理由: 文字単位の役割が残る）
  - **パラグラフ + センテンス**: 買うもの: 段落の繰り返しを直接見る。コスト: 1 段落内の文の繰り返しを見落とす。センテンスが覆う。成り立たない所: 細かいループ。（採らなかった理由: センテンスで足りる）
  - **文字だけ（現状）**: 買うもの: 変更が最も小さい。コスト: 947 文字周期を捕まえられない。成り立たない所: 649 のループ。（採らなかった理由: 649 を捕まえられない）

### Definition

- `Unit.thinking-scrub`(kept): ループを取り除く main function は同じ。検出の単位は check。

## 03: フォローアップに何を注入するか

### Context

- owner は、フォローアップに「対象の文もしくは単語」を注入したいと述べた。
- pi-repetition-guard は、切り詰めた反復単位の見本を steer に添える。loop-police は再導出の説明を送る。
- ADR 028 は「跡に何も足さない」と決めた。フォローアップのサンプルは、その例外になる。
- 分かっていないこと: サンプルがループからの脱出を助けるか、真似を促すか。

### Scope

- 変更:
  - behaviour: in — フォローアップにサンプルを入れる。
  - refactor: out — 検出の芯は entry 02 のまま。サンプルの選択は小さな関数で足りる。
  - dependency: out — 新しい依存は無い。
  - naming: out — 既存の名前は変えない。
  - format: out — 形だけを変える箇所は無い。
  - prose: in — README のフォローアップの説明。
- 品質:
  - speed: in — サンプルの選択は run の単位の走査で足りる。
  - security: out — 新しい入力面が無い。
  - compatibility: in — サンプルは 200 文字で切る。空なら引用しない。
  - errors: in — サンプルの選択が失敗しても、フォローアップは送る。
- 運用:
  - deploy: out — このスターターに deploy は無い。
  - migration: out — 既存のセッションは書き換えない。
  - logs and monitoring: out — フォローアップはトランスクリプトに出る。

### Research & Trial

- pi-repetition-guard は「切り詰めた反復単位の見本」を steer に添え、1 論理ターン 2 回までにする。止めた後に実答が得られたという第三者報告は無い。
- loop-police は回復メッセージで再導出を説明する。繰り返しの内容そのものは引用しない。
- 649 のクラスタ 1 は 44 単位・949 文字で、最頻の 3 文は `The owner. / The cycle. / Good.` のような並びだった。最頻の語は `The`。
- サンプルが助けになるか、真似を促すかは、どのツールも報告していない。
- trial はしていない。

### Decision

- Status: **accepted**
- Adopted:
  - **a**: run の中で最も多い 3 文の連続を、200 文字で切って custom message に入れる。周期が 3 以下なら周期そのものを使う。
- Options:
  - **b**: 周期の先頭 3 文。買うもの: 単純。コスト: `The consult_worktree ...` のようなツール予告が先頭に来ることがある。成り立たない所: フィラーが伝わりにくい。（採らなかった理由: 何が繰り返っているか伝わりにくい）
  - **c**: 最頻の 1 文。買うもの: 短い。コスト: フィラーそのもので、文脈が足りない。成り立たない所: 3 文の並び。（採らなかった理由: 文脈が足りない）
  - **d**: 引用しない。買うもの: フィラーを戻さない。コスト: モデルが何を避けるべきか分からない。成り立たない所: owner の求める「対象の文」。（採らなかった理由: owner の求めを満たさない）
  - **単語**: `The` のような最頻語を入れる。買うもの: 最短。コスト: 繰り返しているトークンそのものを強化する。成り立たない所: ループの単位は文。（採らなかった理由: ループの単位は文）

### Definition

- `Unit.thinking-scrub`(kept): ループを取り除く main function は同じ。サンプルは route。
